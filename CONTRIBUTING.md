# Contributing

Use a pull request for changes to protected branches.

Before opening a pull request:

1. Keep secrets and signing material out of the repository.
2. Add or update tests when behavior changes.
3. Run the repository's documented validation commands.
4. Keep unrelated changes out of the same pull request.
5. Include verification evidence for security, release, Android, CI/CD, or infrastructure changes.

Pull requests should explain the change, the risk, and how it was verified.
